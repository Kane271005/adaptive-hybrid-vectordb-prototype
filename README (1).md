# Adaptive Hybrid Vector Database Prototype

This repository contains the prototype accompanying the report:

**An Adaptive Hybrid Query Processing Framework for Vector Databases in Modern AI Applications**

## Scope

The prototype evaluates the **online query-planning and feedback components** of the proposed framework.

The **offline physical-design controller is not implemented** in this prototype. The maintained portfolio is fixed during the experiment.

## Dataset and Experimental Setup

The experiment uses:

- 10,000 synthetic `float32` vectors
- 32 dimensions
- 20 Gaussian clusters
- Random seed: `20260918`
- Filter passing fractions: 1%, 10%, 50%, and 100%
- 20 calibration queries
- 60 separate evaluation queries
- `k = 10`
- Squared Euclidean distance

Exact filtered search is used to construct the ground truth for Recall@10.

## HNSW Configuration

The HNSW index uses:

- `M = 16`
- `efConstruction = 100`

Three HNSW vector-first configurations are available:

- **HNSW-low**: `efSearch = 32`, `candidates = 100`
- **HNSW-medium**: `efSearch = 64`, `candidates = 500`
- **HNSW-high**: `efSearch = 128`, `candidates = 2000`

An **Exact-filter-first** alternative is also available.

## Compared Policies

The prototype compares three policies:

1. **Fixed HNSW**  
   Always uses `HNSW-medium`.

2. **No feedback**  
   Selects the lowest-latency calibrated plan predicted to satisfy the Recall@10 target of 0.95. The prediction table is frozen during evaluation.

3. **Adaptive**  
   Starts from the same calibration table and updates the selected plan's latency estimate after each query using a moving-average weight of 0.20. Recall is audited every tenth query and the recall estimate is updated with the same weight.

## Evaluation Procedure

Each policy is evaluated on the same 60 test queries at filter passing fractions of:

- 1%
- 10%
- 50%
- 100%

The experiment is repeated three times using the same query set. Policy execution order is shuffled for each query to reduce systematic timing-order effects.

Therefore, each selectivity-policy result contains **180 timed executions**, but these are repeated timings of 60 queries rather than 180 independent queries.

Ground-truth computation used only for evaluation is excluded from normal query latency. Adaptive end-to-end latency includes planning, search execution, model updates, and synchronous recall audits.

## Experimental Environment

The prototype was executed in Google Colab using:

- Python 3.13.15
- NumPy 2.1.3
- Faiss 1.15.1

## Running the Prototype

1. Open `VectorDB_Prototype.ipynb` in Google Colab.
2. Run all cells from top to bottom.
3. The notebook will:
   - generate the synthetic dataset;
   - build the HNSW index;
   - create exact filtered ground truth;
   - calibrate the candidate plans;
   - evaluate Fixed HNSW, No feedback, and Adaptive policies;
   - record adaptation overhead;
   - generate the final summary tables and figures.

## Important Note

The worked example in the report containing **0.97 recall and 71 ms latency is hypothetical** and is not an experimental result.

The measured results reported in the prototype evaluation are generated by this implementation.

The prototype evaluates only the online planning and feedback components. The complete two-level framework, including offline portfolio adaptation, remains conceptual.
